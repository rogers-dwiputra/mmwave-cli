# Validation Report: Raspberry Pi Capture vs. mmWave Studio Ground Truth
**Experiment Date:** 2026-05-10 (Outdoor — Bridge Site)  
**Validation Date:** 2026-05-12  
**Author:** Rogers Dwiputra Setiady — IMRSL, Muroran Institute of Technology  

---

## 1. Objective

Validate that the automated radar capture pipeline running on a Raspberry Pi 5
(`mimo.py` + `mmwcas` Cython extension → TDA2XX) produces data of equivalent quality
to captures taken via the mmWave Studio GUI (Windows, ground-truth path).
This comparison is a prerequisite before using the RPI pipeline as the sole acquisition
system in structural health monitoring deployments.

## 4. Validation Method

### 4.1 SLC Image Comparison
The Signal Processing chain for both datasets:
```
ADC data → Range FFT → Doppler FFT → Beamforming → SLC image [257 angle bins × 3992 range bins]
```
Processed by `mimo_processing.process_capture()` in `~/IoSAR-EdgeProcessing/mimo_processing.py`.
Output: `SLC.png` (dB scale, colormap `viridis`, range 110–160 dB).

Comparison metric: visual inspection of target peak position, amplitude, sidelobe pattern,
and noise floor in a single representative frame.

### 4.2 Range Profile Comparison
Per-frame range profile extracted as the maximum across all angle bins.
Output: `range-profile.png` (dB scale, x-axis = range in meters).

Comparison metric: peak position (m), peak amplitude (dB), noise floor level (dB).

### 4.3 Parameter File Comparison
`.mmwave.json` config files generated by `export_config_to_json()` (`utility.py`) were
inspected to confirm the parameters actually sent to the TDA board.
Matlab's `parameter_file_gen_json()` converts these to `test_param.m` for cross-verification.

| Target position (angle) | X ≈ 0° (broadside) | X ≈ 0° (broadside) | ✓ |

**Conclusion: SLC images are visually identical. Target localization and SNR are equivalent.**

### 5.2 Range Profile

| Metric | GT (frame 224/500) | RPI (frame 110/110) | Agreement |
|--------|--------------------|----------------------|-----------|
| Peak range | ~10 m | ~10 m | ✓ |
| Peak amplitude | ~86 dB | ~86 dB | ✓ |

| SNR (peak − noise) | ~31–36 dB | ~31–36 dB | ✓ |

**Conclusion: Range profiles are visually identical.**

### 5.3 Frame Periodicity Note

The RPI capture used `framePeriodicity = 100 ms` (10 Hz) instead of 50 ms (20 Hz) because
the Raspberry Pi had **not been synchronized** with the latest repository before the experiment.
Commit `e183e85` (2026-05-01) had changed `framePeriodicity` from 100 → 50 ms, but the Pi
was still running the pre-sync version.

This affected temporal resolution (fewer frames per second) but did **not** affect:
- Spatial/range resolution
- SLC image quality
- SNR
- Target detection capability

The `.mmwave.json` file faithfully recorded what was actually configured on the Pi (`100 ms`),
confirming the configuration path `mimo.py → mmwcas.pyx → TDA → .mmwave.json` is correct.

---

## 6. Conclusion

**The RPI automated capture pipeline produces radar data of equivalent quality to the
mmWave Studio GUI ground-truth path.**

Specifically:
- SLC images are spatially identical (same target position, peak amplitude, clutter pattern)
- Range profiles are identical (same peak range, amplitude, SNR)
- All RF waveform parameters are correctly propagated from `config_dict` in `mimo.py`
  through the `mmwcas` Cython extension to the TDA hardware

The pipeline is validated and ready for deployment as the sole acquisition system.
The next step is to confirm `framePeriodicity = 50 ms` operates correctly end-to-end
(Indoor Experiment 2026-05-12 — see `experiment-log/20260512 Indoor/`).
